# Contributing

Use Windows with the .NET 10 SDK and Node.js 24/npm. Run `./build.ps1` for a portable build; Node is a build tool and is not needed by portable users. See [README](README.md#build-from-source) for copied-save test commands. Save-writing changes should cover encrypted round trips, unrelated Pokémon preservation, backups, stale files and invalid/full destinations. Never test against your only save.

Keep UI strings aligned across PT-BR, English and Spanish. Preserve the transaction boundary in `Engine/SaveService.cs`; UI actions must not write save bytes directly. Describe limitations when changing nature suggestions. Keep the vendored PKHeX revision and notices explicit when updating it.

The web workbench uses one inline workspace, Anime.js with reduced-motion/cleanup, and embedded assets with no runtime CDN. Preserve local Host/Origin/authentication checks, expected hashes, operation receipts and private runtime diagnostics. Verify actual desktop/390px interactions; a build or generated design image is not evidence of working UI. Exercise refresh, out-of-order responses and ambiguous commit outcomes when changing the host/client boundary.

The creation picker must retain the complete Engine catalog (currently 364 species), National Pokédex ID order, name/exact-ID search, lazy images and touch/keyboard selection. Species changes preserve other creation fields while resetting moves/Plus to automatic generation and selecting a supported form/gender. Automatic shiny must remain null rather than being coerced into non-shiny. Keep all 25 offline ball PNGs and nature/Mint effect labels aligned across languages, including neutral Mints and effective nature following the original when no override exists.

Alpha planning is a no-write operation. Compatible can propose Alpha encounter, minimum level and necessary move changes; explicit Custom preserves requested origin and exposes the real PKHeX report, even when invalid. Both modes require Scale 255 and at least three IVs 31; Custom never bypasses these invariants. Show the actual diff before applying it to a draft, retain session/hash/revision freshness checks and clear the policy when Alpha is disabled. Do not rewrite unrelated identity or falsify legality findings. See the [editing contract](docs/EDITING.md#plan-an-alpha-conversion).

Reject stale selection/box/validation responses even when cancellation races with completion. Keep post-write receipt failures as uncertain outcomes requiring reconciliation, and test backup junction/reparse handling without using private saves. Show the host's reported version in the UI. The [2.1.0 audit](docs/audits/2026-11-13-alpha-review.md) is the record of executed checks, not a substitute for validating a changed path.

Artwork must keep exact visible form/shiny identity. Preserve `cache/pokemon/v2`, explicit unavailable responses, bounded retries and recovery updates to every mounted copy of a sprite. Never present a different form or normal image as a successful shiny result. Test resolver changes with `dotnet run --project HostTests/HostTests.csproj -- --sprites`; live network probes are optional. See the [harness guide](HostTests/README.md). Label historical Engine/HTTP/sprite/live results instead of reporting them as freshly executed.

Bug reports should include application version, Windows version, steps, expected/actual behaviour and a sanitised error. Do not attach saves, backups, tokens, personal paths or trainer details to public issues. Prefer synthetic reproductions. Pull requests should explain the change and checks actually run; distinguish compilation from copied-save tests.

Contributions are distributed under GPL-3.0-or-later. Do not contribute game binaries, game dumps, personal saves or assets without appropriate rights.
